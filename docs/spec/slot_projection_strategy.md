# 插槽投影策略规范（Slot Projection Strategy）

## 问题定义

容器类组件（Tabs/Accordion/Stepper 等）不仅决定“显示哪个面板”，还决定“未显示面板如何生存”。  
在真实页面里，slot 内容可能很重（图表、编辑器、异步轮询、动画）。

两种极端都不可靠：

- 全量渲染 + CSS 隐藏：首屏与内存成本高
- 每次切换都销毁重建：状态丢失、体验抖动

## 核心判断

- 内容投影策略必须成为逻辑层可配置能力，而不是 view 层临时 `if/else`。
- 逻辑层管理策略与生命周期语义，view 层执行具体投影实现。

## 标准解法

### 1) 逻辑层显式策略

容器状态应包含投影策略，例如：

```rust
enum RenderMode {
    Lazy,      // 首次激活才创建，未激活不挂载
    KeepAlive, // 保持挂载，隐藏非激活内容
    Eager,     // 全部立即挂载
}
```

`logic.rs` 负责根据 `RenderMode` 产生可执行投影意图。

### 2) view 层执行策略

- `Lazy`：仅激活项渲染（`Show`/条件挂载），避免无效初始化
- `KeepAlive`：全部挂载，通过可访问隐藏策略切换可见性
- `Eager`：首帧全部渲染，后续只切换显示态

### 3) KeepAlive 生命周期通知

`KeepAlive` 场景下，隐藏不等于停机。  
逻辑层应可发出生命周期命令（如 `NotifyHidden/NotifyVisible`），让子树暂停高成本副作用（动画、轮询、观测器）。

## 分层约束

- `logic.rs`：
  - 允许：`RenderMode` 策略决策、面板生命周期意图
  - 禁止：直接操作 DOM 显隐与子树副作用句柄
- `view.rs` / adapter：
  - 允许：执行挂载/卸载/隐藏策略，转发生命周期通知
  - 禁止：绕过逻辑层硬编码策略分支

## 性能与状态保留约束

- `Lazy` 必须避免重复重建已访问面板（除非策略明确要求）。
- `KeepAlive` 必须支持“隐藏即降耗”机制，防止不可见面板持续耗资源。
- 策略切换必须可收敛：切换 `RenderMode` 后，面板可见性、状态保留与副作用状态一致。

## 测试要求

- 单测：`RenderMode` 下的投影决策与生命周期命令输出正确。
- 集成测试：
  - `Lazy` 下未激活面板不挂载
  - `KeepAlive` 下切换后状态不丢失
  - 隐藏面板副作用可暂停并可恢复
- 回归测试：重内容 slot（如编辑器/图表）在多次切换下无明显卡顿与状态漂移。
